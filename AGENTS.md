Flypack is an agent-first planner for live production crews: signal, network, audio and video
patching, racks, and cable runs measured on the venue's own floor plan, with an MCP server so
agents can plan a show as easily as people can. There is no application code yet. The product
brief is [docs/PRODUCT.md](docs/PRODUCT.md); the first prototype gets scoped in a wayfinder
session that starts from [the research notes](docs/research/2026-10-29-agent-first-patching-tool.md).

| Path | Role |
| --- | --- |
| `brand/` | Logos, app icons, favicons, social cards, the tagline and the design tokens. Generated by `brand/scripts/build.mjs` |
| `brand/tokens/flypack.css` | Every shadcn/ui and Tailwind v4 token. Any UI imports this, never its own colors |
| `docs/PRODUCT.md` | What Flypack must do, and the decisions still open |
| `docs/adr/` | Decisions already made, one file each |
| `docs/research/` | Research notes with sources |

## Ground rules

- **License:** AGPL-3.0 ([ADR 0001](docs/adr/0001-agpl-license.md)). Everything that runs in a
  hosted Flypack is in this repo. Check a dependency's license before adding it; tldraw's
  commercial license is one that does not fit.
- **Spec references, not code sources:** LZ Cable Planner is proprietary and SigPath has no
  license. Read them for behaviour, copy nothing. EasySchematic (AGPL) code may be reused with
  attribution.
- **UI:** shadcn/ui on Base UI with Tailwind v4 ([ADR 0002](docs/adr/0002-ui-stack.md)). Gaff
  yellow `#F5C400` means brand, live or selected, and is never text on a light surface. The full
  rules are in [brand/tokens/README.md](brand/tokens/README.md).

## Secrets: this repository is public

Every commit, PR, issue, review comment, CI log and screenshot is public and permanent.

- **Secrets come from environment variables at runtime, and nowhere else.** No keys, tokens,
  passwords or connection strings in code, config, tests, fixtures, docs or comments, and no
  real values as defaults (`process.env.X ?? "sk-..."`). Read them in one config module that
  fails fast, naming the missing variable but never printing a value.
- **Env files stay local.** `.env` and `.env.*` are gitignored. Commit `.env.example` with every
  variable name and a placeholder value only.
- **Nothing secret reaches the browser.** Variables with a public prefix (`VITE_`,
  `NEXT_PUBLIC_`, `PUBLIC_`) are bundled into client code. Only public identifiers go there.
- **Never echo a value.** Not in logs, error messages, test snapshots, PR bodies, issue comments
  or screenshots. Redact before posting command output. When a secret is needed, ask the
  developer to set it; never ask them to paste it into chat.
- **Before every commit, check the diff for secrets**, including generated files and lockfiles.
- **A leaked secret is burned.** If one is committed or posted anywhere public, rotate it first,
  then remove it. Rewriting history does not un-leak it.
- Keep machine-specific details out too: hostnames, ports, home paths and internal URLs.

## Before you…

- **design or build UI**: read [brand/tokens/README.md](brand/tokens/README.md)
- **change a logo, icon, social card or the tagline**: edit `brand/scripts/build.mjs`, run
  `pnpm build` in `brand/scripts`, and read [brand/README.md](brand/README.md) and
  [brand/TAGLINE.md](brand/TAGLINE.md)
- **make a product or architecture decision**: check [docs/PRODUCT.md](docs/PRODUCT.md) and
  `docs/adr/`, and record the decision as the next numbered ADR
- **open or land a PR**: code goes through a PR and lands as a squash merge with a
  `<type>(<scope>): <subject>` title. Docs that later work starts from (plans, ADRs, research,
  the product brief, agent instructions) can go straight to `main` as `docs(<scope>): ...`.
  UI changes show before and after screenshots.
